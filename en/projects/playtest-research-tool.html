Code on GitHub

About the project

A university practicum on “Conducting playtests and user research”: the task was to study the field and build a product that automates one of its processes, using an OOP language (Java) and Python. I chose this topic deliberately — it's the closest to what interests me in game development: how a player thinks, what they enjoy and why.

Idea

The tool scans game session logs for signs of “rage input” (furious, frustrated input) and patterns of the player getting stuck or going in circles, timestamps them, and syncs those timestamps with the session's screen recording — so problem moments can be found quickly without rewatching the whole recording.

Scope

Parsing native logs of real game engines is out of scope; the tool works with a fixed custom event schema (input_action, progression_event, session_start/session_end, no coordinates). The input data is synthetic logs imitating different genres and game pacing rather than the author's own game (my roguelite project isn't ready for that role yet).

Status

Currently in the research phase — studying the domain and existing solutions before development begins.
